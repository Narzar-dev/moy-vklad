# План проекта мобильного приложения «Мой вклад»

> Рабочее название. Версия документа: 1.0  
> Язык интерфейса: русский  
> Возраст основной аудитории: 5–9 лет  
> Тип продукта: семейный тренажёр самостоятельности и бытовых навыков

## 1. Резюме проекта

«Мой вклад» — мобильное приложение для ребёнка и родителя, которое помогает постепенно осваивать повседневные обязанности, замечать потребности окружающих, проявлять инициативу и доводить начатое до конца.

Приложение не должно превращать домашние дела в оплачиваемую очками работу. Опыт используется как временная обратная связь во время освоения навыка. После закрепления привычки очки за неё постепенно исчезают, а навык переносится в раздел «Я это умею».

Главный результат продукта — не длительное удержание ребёнка в приложении, а рост самостоятельности вне экрана:

- ребёнок чаще начинает дело без напоминаний;
- количество напоминаний и семейных конфликтов уменьшается;
- освоенные действия продолжают выполняться после отмены опыта;
- ребёнок умеет попросить помощь и исправить ошибку;
- ребёнок замечает полезные дела и иногда инициирует их самостоятельно.

Продукт не является средством психотерапии, диагностики или лечения.

## 2. Видение и продуктовые принципы

### 2.1. Видение

Помочь ребёнку перейти по цепочке:

```text
Делаем вместе → Делаю по подсказке → Делаю сам → Сам замечаю → Беру ответственность
```

### 2.2. Основные принципы

1. **Самостоятельность важнее послушания.** Ребёнок учится понимать договорённость, планировать действие, просить помощь и исправлять последствия.
2. **Опыт показывает рост, но не определяет ценность ребёнка.** Нельзя называть ребёнка «хорошим», «плохим», «ответственным» или «безответственным» на основании очков.
3. **Выбор поддерживает мотивацию.** Ребёнок может выбирать порядок дел и следующий осваиваемый навык из безопасных вариантов взрослого.
4. **Обратная связь описывает действие и его пользу.** Например: «Ты сам вспомнил полить цветок. Теперь у него есть вода».
5. **Навык должен отделиться от награды.** После освоения регулярного действия начисление опыта прекращается.
6. **Ошибки не наказываются внутри приложения.** Пропуск становится поводом изменить план, добавить подсказку или попросить помощь.
7. **Приложение выводит ребёнка из экрана.** Взаимодействие должно занимать несколько коротких подходов общей продолжительностью не более 3–5 минут в день.
8. **Безопасность и приватность выше вовлечённости.** Нет рекламы, публичных профилей, чатов, рейтингов, лутбоксов и скрытого трекинга.
9. **Задачи не делятся на «мальчиковые» и «девочковые».** Выбранный пол влияет только на русскую грамматику текстов.

## 3. Целевая аудитория и роли

### 3.1. Ребёнок 5–6 лет

- читает мало или ещё не читает;
- воспринимает конкретные короткие инструкции;
- нуждается в картинках, озвучивании и участии взрослого;
- осваивает одно новое действие за раз;
- ответственность описывается словами «мой вклад», «я помог», «я сделал свою часть».

### 3.2. Ребёнок 7–8 лет

- способен работать по короткому списку;
- может выбирать порядок действий;
- начинает понимать договорённость и простые последствия;
- учится оценивать: «сам», «с напоминанием», «с помощью».

### 3.3. Ребёнок 9 лет

- может планировать дела на день или неделю;
- способен взять постоянную область ответственности;
- участвует в семейном обсуждении правил;
- учится самостоятельно исправлять пропуски и ошибки.

### 3.4. Родитель или другой законный представитель

- создаёт профиль ребёнка;
- выбирает безопасные и посильные действия;
- настраивает расписание и необходимый контроль;
- подтверждает инициативы;
- проводит короткое еженедельное обсуждение;
- адаптирует ожидания под темперамент и особенности развития ребёнка.

## 4. Обязательная персонализация по полу ребёнка

### 4.1. Требование

Во время создания каждого детского профиля родитель обязан выбрать пол ребёнка:

- **Мальчик**;
- **Девочка**.

Поле не имеет значения по умолчанию и не может быть пропущено. Перед выбором показывается пояснение:

> «Это нужно, чтобы приложение правильно составляло русские фразы: “сделал/сделала”, “сам/сама”, “готов/готова”. Набор заданий и возможности приложения одинаковы для всех детей».

Родитель может изменить выбор в настройках профиля. Приложение никогда не определяет пол по имени, фотографии, голосу или выбранному аватару.

### 4.2. Использование в текстах

В модели данных используется поле:

```text
child_gender: male | female
```

Для интерфейсных сообщений применяется шаблонизатор с грамматическими вариантами. Рекомендуется ICU MessageFormat или аналогичный механизм, а не строки вида `сделал(а)`.

Пример внутреннего шаблона:

```text
{gender, select,
  male {Ты сам заметил полезное дело, решил его выполнить и сделал это.}
  female {Ты сама заметила полезное дело, решила его выполнить и сделала это.}
}
```

Обязательные пары для проверки контента:

| Мужская форма | Женская форма |
|---|---|
| сам | сама |
| сделал | сделала |
| решил | решила |
| заметил | заметила |
| попробовал | попробовала |
| попросил | попросила |
| готов | готова |
| справился | справилась |
| начал | начала |
| исправил | исправила |

### 4.3. Ограничения

- Пол не влияет на каталог заданий, сложность, опыт, награды, цветовую схему или персонажей.
- Пол не передаётся в рекламные или аналитические системы.
- В аналитике по возможности используется только возрастная группа; пол подключается лишь к исследованиям, где он действительно необходим и разрешён согласием родителя.
- Весь пользовательский интерфейс и все сообщения ребёнку должны иметь проверенные мужскую и женскую версии.

## 5. Основная продуктовая модель

Приложение различает три типа активности.

| Тип | Кто инициирует | Назначение |
|---|---|---|
| Обязанность | Семья договаривается заранее | Создание регулярности |
| Новый навык | Ребёнок и взрослый выбирают вместе | Развитие компетентности |
| Инициатива | Только ребёнок | Умение замечать, решать и действовать |

### 5.1. Еженедельный цикл

1. Родитель и ребёнок выбирают 2–4 актуальных действия.
2. Ребёнок выбирает порядок выполнения там, где это безопасно.
3. В течение недели приложение фиксирует не только выполнение, но и уровень помощи.
4. В конце недели семья обсуждает, что стало легче и что нужно изменить.
5. Освоенные действия переходят в «Я это умею».
6. Ребёнок выбирает следующий навык из двух или трёх предложений.

### 5.2. Ежедневный цикл ребёнка

1. На экране отображаются не более трёх основных карточек.
2. Ребёнок нажимает «Начать».
3. Приложение показывает или озвучивает шаги и предлагает отложить телефон.
4. После выполнения ребёнок выбирает результат:
   - «Сделал сам» / «Сделала сама»;
   - «Понадобилась подсказка»;
   - «Мы сделали вместе»;
   - «Пока не получилось»;
   - «Нужна помощь».
5. Приложение даёт короткую содержательную обратную связь.
6. Подтверждение взрослого происходит позже и не задерживает ребёнка у экрана.

## 6. Задачи и библиотека навыков

### 6.1. Структура карточки задачи

Каждая предустановленная задача содержит:

- название для ребёнка;
- нейтральное описание для родителя;
- категорию;
- рекомендуемый возраст;
- ориентировочную продолжительность;
- уровень надзора взрослого;
- 2–5 визуальных шагов;
- базовый опыт;
- расписание;
- критерий завершения без требования идеальности;
- предупреждения по безопасности;
- мужские и женские варианты сообщений.

### 6.3. Запрещённые категории

Нельзя начислять опыт за:

- «не плакал», «не злился» или «был хорошим»;
- объятия, проявление любви и дружбу;
- беспрекословное согласие со взрослым;
- съеденную до конца еду;
- туалет, массу тела или ограничение пищи;
- оценки и победы вместо усилия и процесса;
- хранение секретов от безопасного взрослого;
- отказ от сна, отдыха или собственных потребностей ради других;
- уход за маленьким ребёнком без взрослого;
- потенциально опасные действия без соответствующего контроля.

Для учёбы отмечается процесс: «начал», «занимался согласованное время», «попросил объяснить», но не итоговая оценка.

## 7. Механика инициативы

### 7.1. Назначение

Инициатива показывает переход от выполнения указаний к самостоятельному обнаружению потребности:

```text
Заметил → Решил → Сделал или попросил помощь → Оценил пользу → При необходимости повторил
```

Инициатива является отдельным типом активности и не может быть назначена родителем заранее.

### 7.2. Точка входа

На главном экране постоянно доступна кнопка:

> ✨ Я сам придумал  
> ✨ Я сама придумала

Кнопка доступна независимо от выполнения плановых задач. Родитель не должен использовать обязательные дела как условие права на инициативу.

### 7.3. Сценарий добавления

1. Ребёнок нажимает «Я сам придумал» / «Я сама придумала».
2. Выбирает категорию:
   - «Заметил и сделал» / «Заметила и сделала»;
   - «Помог» / «Помогла»;
   - «Навёл порядок» / «Навела порядок»;
   - «Исправил ошибку» / «Исправила ошибку»;
   - «Придумал, как сделать лучше» / «Придумала, как сделать лучше»;
   - «Научился сам» / «Научилась сама».
3. Выбирает готовую пиктограмму и действие либо просит взрослого записать короткий текст.
4. Отвечает на один вопрос: «Кому или чему это помогло?»
5. Запись получает статус «Ждёт семейного обсуждения».
6. Родитель подтверждает тип действия и безопасность.
7. Ребёнок получает содержательную обратную связь и, при соблюдении условий, опыт.

Для MVP не требуется загрузка фотографии, видео или голосовой записи. Свободный текст вводит родитель, а ребёнок может выбрать иконки. Это снижает объём персональных данных и сложность модерации.

### 7.4. Опыт за инициативу

| Ситуация | XP |
|---|---:|
| Самостоятельно замеченное и выполненное полезное действие | 10 |
| Инициатива с освоением нового безопасного навыка | 15 |
| Самостоятельное исправление собственной ошибки | 10 |
| Хорошая идея, реализованная вместе со взрослым | 5 |
| Небезопасное или неполезное действие | 0, без наказания |

Ограничения:

- опыт начисляется максимум за одну инициативу в день;
- остальные записи сохраняются в дневнике без очков;
- повторение одного и того же действия не считается новой инициативой бесконечно;
- после 2–3 повторений приложение предлагает сделать действие постоянной ответственностью;
- качество, масштаб и скорость не влияют на количество XP;
- родитель не может создать инициативу от имени ребёнка.

### 7.5. Подтверждение инициативы взрослым

Родитель оценивает только три критерия:

1. Ребёнок выбрал действие самостоятельно.
2. Действие было безопасным или выполнялось с нужной помощью.
3. Действие помогло человеку, животному, общему пространству или самому ребёнку освоить полезный навык.

Варианты решения:

- «Да, это была инициатива»;
- «Хорошая идея, вы сделали это вместе»;
- «Такое можно делать только со взрослым»;
- «Обсудить, почему результат оказался неполезным».

Небезопасная попытка не называется провалом. Пример сообщения:

> «Ты хотел помочь — это важно. Пользоваться этим средством можно только со взрослым. В следующий раз сначала позови меня».

### 7.6. Компас самостоятельности

Вместо рейтинга ребёнок собирает признаки развивающейся самостоятельности:

- сам заметил / сама заметила;
- сам начал / сама начала;
- предложил решение / предложила решение;
- попросил помощь вовремя / попросила помощь вовремя;
- исправил ошибку / исправила ошибку;
- позаботился об общем пространстве / позаботилась об общем пространстве.

Компас не обнуляется, не сравнивается с другими детьми и не имеет ежедневной серии.

## 8. Система опыта и освоения

### 8.1. Базовая шкала

| Сложность действия | XP |
|---|---:|
| До 2 минут, один простой шаг | 5 |
| 2–7 минут, обычная рутина | 10 |
| 7–15 минут или несколько шагов | 15 |
| Новый навык или небольшой семейный проект | 20 |

Дополнительные признаки прогресса:

- начал без напоминания / начала без напоминания: `+5 XP`;
- попробовал новый сложный шаг / попробовала новый сложный шаг: `+5 XP`.

Бонусы не должны суммарно превышать `+5 XP` за одно действие. Дневной лимит — 40–50 XP. Повторное нажатие и незапланированное многократное выполнение одной рутины не дают дополнительного опыта.

### 8.2. Уровни общего пути

Каждые 100 XP открывают новую главу, иллюстрацию или возможность выбора, но не материальный приз. Уровень нельзя купить, потерять или сравнить с уровнем другого ребёнка.

Примеры открытий:

- новый элемент личной комнаты или сада;
- выбор следующего семейного мини-проекта;
- новая история;
- возможность выбрать музыку для семейной уборки;
- право провести короткое семейное обсуждение вместе со взрослым.

### 8.3. Постепенное угасание опыта

Для каждого навыка действует собственная прогрессия:

1. **Обучение:** первые 5–7 успешных повторений дают полный XP.
2. **Практика:** следующие 5–7 повторений дают половину XP.
3. **Проверка самостоятельности:** приложение наблюдает, уменьшается ли количество подсказок.
4. **Выпуск:** навык переносится в «Я это умею», ребёнок получает финальную карточку, ежедневный XP прекращается.

Критерии выпуска настраиваются родителем. Рекомендуемый ориентир: действие успешно выполнено не менее четырёх раз из последних пяти и преимущественно без прямой помощи.

Перед снижением опыта приложение сообщает:

> «Очки помогали тебе учиться. Теперь ты умеешь это сам».  
> «Очки помогали тебе учиться. Теперь ты умеешь это сама».

## 9. Уровни ответственности

Ответственность отслеживается отдельно для каждого навыка, а не как глобальный ярлык ребёнка.

| Уровень | Название | Поведение |
|---:|---|---|
| 1 | Вместе | Выполняет со взрослым |
| 2 | По шагам | Следует визуальной инструкции |
| 3 | С напоминанием | Выполняет после одной спокойной подсказки |
| 4 | Самостоятельно | Вспоминает и выполняет в согласованное время |
| 5 | Ответственно | Планирует, замечает необходимость и исправляет пропуск |

Возрастная подача понятия:

- 5–6 лет: «Это твой вклад в нашу семью»;
- 7–8 лет: «Мы договорились, и ты выполнил свою часть» / «выполнила свою часть»;
- 9 лет: «Ты сам планируешь эту область и исправляешь ситуацию, если что-то не получилось» / женская форма соответственно.

Просьба о помощи считается ответственным действием, а не неудачей.

## 10. Вознаграждения и последствия

### 10.1. Допустимые вознаграждения

- конкретная обратная связь об усилии, стратегии и пользе;
- визуализация освоенного навыка;
- выбор порядка дел;
- выбор следующего навыка из безопасных вариантов;
- косметическое оформление без валюты и покупок;
- новая глава истории;
- право выбрать семейную игру, музыку или совместное занятие;
- роль в семейном проекте;
- карточка «Я это умею».

### 10.2. Недопустимые механики

- отнятие XP или уровня;
- обнуление серии дней;
- грустный, больной или умирающий персонаж;
- красные «провалы» и стыдящие сообщения;
- таблицы лидеров и сравнение братьев, сестёр или друзей;
- случайные награды и лутбоксы;
- виртуальная валюта;
- ограниченные по времени предложения;
- сладости, деньги или дополнительное экранное время как встроенная награда;
- блокировка ранее заработанного результата.

### 10.3. Пропуск задачи

Приложение показывает нейтральный экран:

> «Сегодня не получилось. Что поможет завтра?»

Варианты:

- напоминание;
- другое время;
- разделить на шаги;
- помощь взрослого;
- временно заменить задачу.

Реальные логические последствия обсуждаются в семье вне приложения. Приложение не лишает ребёнка еды, сна, общения, любви или базовых потребностей и не рекомендует такие меры.

## 11. Интерфейс и информационная архитектура

### 11.1. Детский режим

Основные экраны:

1. **Сегодня** — до трёх карточек и кнопка инициативы.
2. **Карточка действия** — картинка, озвучивание, 2–5 шагов, «Начать».
3. **Как получилось** — выбор уровня помощи.
4. **Инициатива** — категория, пиктограмма, короткое описание с помощью взрослого.
5. **Я это умею** — коллекция освоенных навыков.
6. **Компас самостоятельности** — признаки инициативы без рейтинга.
7. **Мой путь** — главы и спокойная визуализация опыта.

Требования:

- крупные зоны нажатия;
- минимум текста;
- озвучивание всех ключевых действий;
- понятные пиктограммы с текстовой подписью;
- отсутствие бесконечной прокрутки;
- отсутствие таймеров, создающих тревогу;
- спокойная короткая анимация;
- предложение закрыть приложение после начала дела;
- поддержка системного размера шрифта и достаточного контраста.

### 11.2. Родительский режим

Основные экраны:

1. Создание и редактирование детских профилей.
2. Обязательный выбор пола и возрастной группы.
3. Выбор текущих навыков.
4. Редактор расписания и напоминаний.
5. Подтверждение инициатив.
6. Настройка требуемого уровня надзора.
7. Недельный обзор без оценок и рейтингов.
8. Настройки приватности, экспорт и удаление данных.

Вход защищается PIN-кодом или системной аутентификацией устройства. Детскому режиму недоступны покупки, настройки данных и внешние ссылки.

### 11.3. Уведомления

- выключены по умолчанию для ребёнка;
- настраиваются родителем;
- не содержат вины, срочности или угрозы потери результата;
- не отправляются во время сна и учёбы;
- не используют формулировки «Ты снова забыл» или «Твоя серия пропадёт».

Пример:

> «Когда будешь готов, можно посмотреть план на вечер».  
> «Когда будешь готова, можно посмотреть план на вечер».

## 12. Стиль коммуникации

### 12.1. Правильные формулировки

- «Ты сам вспомнил полить растение» / «Ты сама вспомнила полить растение».
- «Ты попробовал другой способ» / «Ты попробовала другой способ».
- «Ты понял, что нужна помощь, и попросил её» / женская версия.
- «Ты забыл убрать краски, а потом сам вернулся и исправил» / женская версия.
- «Сегодня понадобилась подсказка. Это часть обучения».

### 12.2. Запрещённые формулировки

- «Ты хороший/плохой ребёнок»;
- «Ты ленивый/ленивая»;
- «Ответственные дети так не делают»;
- «Ты подвёл семью» / «Ты подвела семью»;
- «Сделай это, чтобы мама тебя любила»;
- «Проиграешь уровень, если не уберёшь»;
- «Настоящий мужчина должен…»;
- «Хорошая девочка обязана…».

## 13. Функциональные требования MVP

### P0 — обязательно для первой версии

- создание родительского профиля;
- создание нескольких детских профилей;
- обязательный выбор пола `male/female` для каждого ребёнка;
- возрастная группа `5–6`, `7–8`, `9`;
- русский интерфейс с мужскими и женскими вариантами всех персональных фраз;
- библиотека минимум из 20 предустановленных действий;
- создание собственного действия родителем;
- расписание и максимум три главные карточки на день;
- фиксация уровня помощи;
- опыт, дневной лимит и защита от повторного начисления;
- угасание XP и выпуск навыка;
- добавление инициативы ребёнком;
- подтверждение инициативы родителем;
- компас самостоятельности;
- нейтральный сценарий пропуска;
- недельный обзор;
- защищённый родительский режим;
- локальное хранение, экспорт и полное удаление данных;
- отсутствие рекламы, покупок, социальных функций и стороннего поведенческого трекинга.

### P1 — после проверки MVP

- синхронизация между устройствами семьи;
- семейный сад или общее пространство, где виден вклад взрослых и детей;
- редактор визуальных инструкций;
- дополнительные наборы навыков;
- адаптивные предложения по уменьшению подсказок;
- печатные карточки и семейный недельный план;
- поддержка нескольких взрослых с разными правами.

### P2 — только после отдельного исследования рисков

- голосовой ввод;
- загрузка фотографий;
- AI-предложения задач;
- интеграции с календарями и умными устройствами;
- дистанционное взаимодействие с педагогом или психологом.

### Не входит в продукт

- социальная сеть;
- публичный профиль ребёнка;
- общий рейтинг;
- чат между детьми;
- реклама;
- магазин виртуальных товаров;
- денежная оплата ребёнку за бытовые обязанности;
- автоматическая психологическая диагностика.

## 15. Нефункциональные требования

### 15.1. Приватность

- режим `privacy by default`;
- сбор только минимально необходимых данных;
- имя ребёнка необязательно;
- вместо полной даты рождения хранится возрастная группа;
- отсутствие геолокации;
- отсутствие рекламных SDK;
- отсутствие публичного контента;
- прозрачное родительское согласие до сетевого сбора детских данных;
- возможность просмотреть, экспортировать и удалить все данные;
- отдельная юридическая проверка требований стран запуска и магазинов приложений.

Для рынков США необходимо учитывать COPPA, включая проверяемое согласие родителя перед сбором персональных данных ребёнка. Для Великобритании применимы принципы Age Appropriate Design Code: интересы ребёнка, минимизация данных, высокая приватность по умолчанию и отсутствие манипулятивных подталкиваний.

### 15.2. Безопасность

- системная или PIN-защита родительского режима;
- шифрование локальной базы и сетевого трафика;
- отсутствие секретов и персональных данных в логах;
- ограниченный срок хранения событий аналитики;
- журнал родительских изменений без доступного ребёнку оценочного рейтинга;
- обязательный анализ сторонних библиотек до выпуска.

### 15.3. Доступность

- озвучивание интерфейса;
- поддержка системного увеличения текста;
- контраст, не зависящий только от цвета;
- отсутствие обязательных жестов высокой точности;
- возможность отключить звук, анимацию и вибрацию;
- адаптация количества шагов и напоминаний для детей с особенностями исполнительных функций.

## 16. Рекомендуемая техническая стратегия

Для MVP целесообразно использовать кроссплатформенную разработку с единым кодом для iOS и Android. Предварительный вариант:

- React Native + TypeScript либо Flutter;
- local-first архитектура;
- локальная SQLite-база;
- отдельный слой русской локализации с грамматическим `gender select`;
- серверная синхронизация только после подтверждения продуктовой гипотезы;
- собственная минимальная аналитика без рекламных идентификаторов.

Окончательный выбор стека принимается после оценки компетенций команды, требований к озвучиванию, анимации, офлайн-режиму и срокам выпуска.

## 17. Бизнес-модель

Предпочтительная модель:

- единоразовая покупка взрослым; либо
- семейная подписка с бесплатным базовым функционалом.

Недопустимы:

- реклама ребёнку;
- продажа детских данных;
- платные лутбоксы;
- покупки из детского режима;
- платное восстановление серий или уровней;
- монетизация тревоги родителя через «оценку нормальности» ребёнка.

## 18. План реализации

### Этап 0. Исследование, 2–3 недели

- 10–15 интервью с родителями детей 5–9 лет;
- отдельные интервью по возрастам 5–6 и 7–9;
- консультация детского психолога;
- проверка языка и гендерных форм редактором;
- карта опасных бытовых действий;
- прототип недельного семейного цикла на бумаге;
- юридическая оценка рынков предполагаемого запуска.

Результат: подтверждённые сценарии, словарь интерфейса, список P0-задач и критерии безопасности.

### Этап 1. Интерактивный прототип, 2–3 недели

- обязательный выбор пола;
- детский экран «Сегодня»;
- карточка действия;
- результат выполнения;
- «Я сам придумал» / «Я сама придумала»;
- подтверждение инициативы;
- выпуск навыка;
- недельный обзор.

Результат: тестируемый прототип без полноценного backend.

### Этап 2. Проверка с семьями, 2 недели

- 5–8 семей;
- наблюдение за чтением и пониманием текстов;
- проверка мужских и женских форм;
- замер времени у экрана;
- поиск ситуаций стыда, торга и «фарма» XP;
- корректировка опыта и количества задач.

### Этап 3. Разработка MVP, 6–10 недель

- профили и локальная база;
- библиотека задач;
- расписание;
- опыт и выпуск навыков;
- инициатива;
- родительский режим;
- доступность;
- приватность, экспорт и удаление;
- автоматические тесты локализации.

### Этап 4. Пилот, 6 недель

- неделя базового наблюдения без XP;
- 3–4 недели использования опыта;
- постепенное отключение XP по освоенным навыкам;
- 1–2 недели наблюдения за переносом навыка;
- интервью с ребёнком и родителем;
- анализ защитных метрик.

### Этап 5. Решение о развитии

Продолжать разработку только при наличии признаков, что самостоятельность сохраняется после угасания опыта и продукт не увеличивает семейные конфликты или экранную зависимость.

## 19. Метрики

### 19.1. Главная продуктовая метрика

**Доля освоенных навыков, которые ребёнок продолжает выполнять без XP и с уменьшившимся количеством напоминаний через 2–4 недели после выпуска.**

### 19.2. Поведенческие метрики

- доля действий, начатых без напоминания;
- среднее количество подсказок на один навык;
- доля запросов помощи до возникновения конфликта;
- количество подтверждённых инициатив в неделю без учёта повторного «фарма»;
- доля инициатив, перешедших в постоянную ответственность;
- количество выпущенных навыков;
- доля семей, проводящих недельный обзор.

### 19.3. Защитные метрики

- среднее экранное время ребёнка в приложении — не более 3–5 минут в день;
- отсутствие роста торга «что я получу?»;
- отсутствие заметного роста конфликтов;
- отсутствие тревоги из-за пропусков;
- отсутствие сравнения детей внутри семьи;
- нагрузка на родителя не превышает несколько минут в день;
- количество небезопасных инициатив и качество их обработки.

Обычные метрики удержания не являются главной целью. Снижение использования после формирования навыков может означать успех продукта.

## 20. Основные риски и меры снижения

| Риск | Мера |
|---|---|
| Ребёнок делает всё только за XP | Постепенное угасание опыта и выпуск навыка |
| Торг за каждое бытовое действие | XP не является валютой и не обменивается на вещи |
| Фарм инициатив | Одна оплачиваемая инициатива в день, повторения переводятся в ответственность |
| Родитель выдаёт требования за инициативу | Инициативу может начать только ребёнок |
| Стыд из-за пропуска | Нейтральные состояния, отсутствие потери прогресса |
| Сравнение детей | Нет рейтингов, общего семейного табеля и лидербордов |
| Гендерные стереотипы | Пол влияет только на грамматику, задачи одинаковы |
| Ошибочная грамматическая форма | Обязательные варианты строк и автоматические тесты локализации |
| Опасное самостоятельное действие | Уровни надзора, предупреждения и родительское подтверждение |
| Приложение становится системой надзора | Минимум подтверждений, отсутствие фото в MVP, недельный обзор вместо постоянного контроля |
| Избыточное экранное время | Короткий цикл и явное предложение отложить устройство |
| Утечка детских данных | Local-first, минимизация данных, отсутствие рекламных SDK |
| Особенности развития воспринимаются как лень | Настройка шагов, подсказок и критериев под конкретного ребёнка |

## 21. Критерии готовности MVP

MVP считается готовым к закрытому пилоту, если:

- родитель может создать профиль только после явного выбора пола;
- все персональные русские фразы корректно отображаются в мужском и женском роде;
- ребёнок может выполнить запланированное действие и указать уровень помощи;
- ребёнок может зарегистрировать инициативу без создания её родителем;
- родитель может безопасно и уважительно обработать инициативу;
- повторное выполнение не позволяет бесконечно получать XP;
- опыт автоматически снижается по мере освоения;
- навык может быть выпущен и продолжить существовать без ежедневных очков;
- пропуск не уменьшает накопленный прогресс;
- в приложении отсутствуют реклама, покупки, рейтинги и социальные функции;
- родитель может удалить все данные;
- ключевые сценарии доступны ребёнку, который ещё не умеет уверенно читать;
- среднее прохождение ежедневного сценария занимает менее одной минуты экранного времени без учёта реального дела.
